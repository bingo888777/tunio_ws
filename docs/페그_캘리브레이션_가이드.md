# 페그 캘리브레이션 가이드 — 4줄 전부

"페그 손잡이를 몇 도 돌리면 음이 몇 센트 변하는가"를 줄마다 구한다.
`task_manager`가 측정 오차로부터 `AdjustPeg`의 `angle_deg`를 계산할 때 쓰는 값이다.

**로봇 없이 기타와 마이크만 있으면 된다.** 도구는 `tools/peg_cal.py`.

> **2026-09-19 측정 완료.** 결과는 `docs/페그_실측표.md`, 원자료는 `docs/peg_data/`.
> 이 문서는 절차 설명으로 남긴다 (줄을 갈면 다시 재야 한다).
>
> 임시값이던 `k = 0.15`(deg/cent)는 1도에 6.67센트, 한 바퀴에 2400센트라는 뜻이었다.
> 실측은 줄에 따라 한 바퀴 181~799센트다. 즉 `k=0.15`는 **줄에 따라 3.0~13.3배**
> 과소 보정한다. 그리고 줄 사이가 4.4배 차이나므로 애초에 상수 하나로는 안 된다.

---

## 0. 전체 소요 시간

한 줄에 10~15분, 4줄이면 **50분~1시간**이다.
시간이 모자라면 회차를 3회에서 2회로 줄인다 (`--rounds 2`). 6번과 1번을 먼저 한다.

---

## 1. 준비

### 기타
- **실제 시연에 쓸 기타.** 다른 기타로 재면 값이 다르다
- **줄을 갈고 하루 이상 지난 상태.** 새 줄은 계속 늘어나 값이 안 잡힌다

### 마이크
실제 측정에 쓸 위치에 둔다(울림통 구멍 앞). 나중에 위치가 바뀌면 재현이 안 된다.

장치가 여러 개면 번호를 먼저 확인한다.

```bash
source /opt/ros/jazzy/setup.bash && source install/setup.bash
python3 tools/pitch_test.py --list
```

쓸 장치가 기본이 아니면 모든 명령에 `--device N`을 붙인다.

### 각도 표시 만들기 — 이게 핵심
- 페그 **손잡이**에 마스킹테이프를 붙이고 유성펜으로 선 하나
- **헤드스톡**에도 테이프를 붙여 기준선

이제 손잡이 선을 시계바늘로 읽으면 된다.

```
12시 → 1시반  =  45도  (1/8바퀴)
12시 →  3시   =  90도  (1/4바퀴)
12시 →  6시   = 180도  (반바퀴)
```

**여기서 재는 각도는 손잡이 각도다.** 기어비로 축 각도를 환산하지 않는다.
로봇도 손잡이를 잡고 돌리므로 기준이 같다.

## 2. 시작 주파수 표

측정은 **목표보다 50센트 낮은 지점**에서 시작한다. 핸드폰 튜너로 대충 맞춰두면 된다.

```
줄  음   목표 Hz     시작값(-50센트)   안전 상한(+200센트)   10센트당
6번 E2    82.407        80.061            92.499          0.477 Hz
5번 A2   110.000       106.869           123.471          0.637 Hz
2번 B3   246.942       239.912           277.183          1.431 Hz
1번 E4   329.628       320.244           369.994          1.910 Hz
```

- **시작값**: 여기 근처에 맞춰놓고 시작한다. ±10센트 오차는 괜찮다
- **안전 상한**: 측정 중 이 주파수를 넘기면 줄이 위험하다. 도구가 자동으로 멈추지만
  눈으로도 확인할 것. 특히 1번 줄
- **10센트당**: 핸드폰 튜너가 Hz만 보여줄 때 감을 잡는 용도

정확히 맞추고 싶으면 이걸로 확인한다. `오차 -50 센트` 근처면 된다.

```bash
python3 tools/pitch_test.py --string 6 --repeat 1
```

## 3. 절대 지킬 것 두 가지

**① 항상 조이는 방향으로만 돌린다.**
페그에는 유격(백래시)이 있어 방향을 바꾸면 처음 얼마간 헛돈다.
값이 튀는 가장 큰 원인이다.

**② 회차를 다시 시작할 때는 아래로 충분히 풀었다가 조여 올린다.**
조인 상태에서 바로 조금 푸는 게 아니다.
예: 6번 줄이면 78Hz까지 풀었다가 80.06Hz로 **조여 올린다.**

그 밖에:
- 손을 뗀 뒤 **3초** 기다렸다가 측정한다 (줄과 기어가 자리를 잡는 시간)
- 목표 음 근처에서 잰다. 줄이 느슨하면 같은 각도라도 덜 변한다

## 4. 각도는 첫 스텝을 보고 정한다

줄마다 몇 도가 적당한지는 기타마다 다르다. 추측하지 말고 **1회차를 프로브로 쓴다.**

### 먼저: 90도가 가장 정확하게 돌릴 수 있는 각도다

45도는 대각선이라 눈으로 재야 하지만, **90도는 손잡이 모양으로 확인된다.**
대부분의 페그 손잡이는 길쭉하다. 그 **긴 축이 세로에서 가로로 바뀌면 정확히 90도**다.
같은 이유로 180도(반대 방향)와 360도(제자리)도 정확히 맞출 수 있다.

**그러니 90도로 시작한다.** 첫 스텝 결과를 보고 조정한다.

```
한 스텝이  5센트 미만  →  180도로 키운다 (긴 축이 반대 방향)
한 스텝이 15~50센트    →  그대로 유지  ← 이 범위가 목표
한 스텝이 50~80센트    →  45도로 줄인다
한 스텝이 80센트 초과  →  Ctrl+C 로 중단, 훨씬 작게 다시 시작
```

### 정확히 안 돌려도 된다

**돌린 각도가 정확할 필요는 없다. 읽은 각도가 맞기만 하면 된다.**
도구가 매번 "실제로 몇 도 돌렸냐"를 물어보므로 47도를 돌렸으면 `47`을 입력하면 된다.
회귀가 기울기를 뽑으므로 등간격일 필요가 전혀 없다.

읽기 오차도 스텝을 쌓고 회차를 평균 내면 상쇄된다.

```
매번 읽기 오차     1스텝만 보면    4스텝 누적    3회차 평균
     5도             9%            4%           3%
    10도            18%            9%           5%
    15도            27%           13%           8%
```

**매번 15도씩 틀리게 읽어도 최종 8%다.** 대체하려는 `k=0.15`가 3.0~13.3배
틀려 있으므로, 10% 안에만 들어오면 충분하고도 남는다.

(실제로 잰 결과 회차간 흩어짐은 6번 15% / 5번 12% / 2번 28% / 1번 18%였다.)

1회차에서 각도가 정해지면 2·3회차는 그 각도로 통일한다.

### 회차당 단계 수

한 회차의 **총 회전량이 목표 +150센트를 넘지 않게** 잡는다.
시작이 -50센트이므로, 한 회차 누적이 200센트 안쪽이면 된다.

한 스텝이 20센트면 → 단계 수 8~9개 가능 (기본 4개면 충분)
한 스텝이 50센트면 → 단계 수 3개

## 5. 실행

```bash
source /opt/ros/jazzy/setup.bash && source install/setup.bash

# 1회차 프로브 겸 본 측정. 90도로 시작 (손잡이 긴 축 세로 -> 가로)
python3 tools/peg_cal.py --string 6 --save peg6.json
python3 tools/peg_cal.py --string 5 --save peg5.json
python3 tools/peg_cal.py --string 2 --save peg2.json
python3 tools/peg_cal.py --string 1 --steps 3 --save peg1.json
```

`--step` 기본값이 90도라 생략했다. 45도로 가야 하면 `--step 45`를 붙인다.
1번 줄만 `--steps 3`인 이유: 고음현은 여유가 적어 한 회차를 짧게 가져간다.

시간이 모자라면 `--rounds 2`를 붙인다. 6번과 1번(양 끝)을 먼저 한다.

### 진행 순서

1. `준비되면 엔터` → 엔터
2. **시작값 측정** — `엔터 후 줄을 뜯으세요`가 나오면 엔터 치고 줄을 뜯는다.
   값이 모이면 자동으로 다음으로 넘어간다 (보통 2번)
3. `조이는 방향으로 돌린 뒤 실제 각도 입력 [90도, 엔터=기본]`
   → **여기서 페그를 돌린다.** 다 돌린 뒤에 각도를 입력
4. 3초 기다렸다가 다시 측정
5. 3~4 반복
6. 회차가 끝나면 구간별 결과가 나온다
7. 줄을 되돌리고(3절 ②) 다음 회차

## 6. 화면 읽는 법

### 스텝마다

```
→ 82.690 Hz   이번 구간 +18.7센트 (+0.207 센트/도)   누적 +55.9센트
```

`이번 구간` 값이 15~50센트면 각도가 적당하다. 4절 표대로 조정한다.

### 회차 끝

```
구간별:
      0→   45도   +18.64센트  +0.2071 센트/도
     45→   90도   +18.59센트  +0.2066 센트/도
     90→  135도   +18.66센트  +0.2074 센트/도
    180→  225도   +18.59센트  +0.2065 센트/도
  평균 +0.2069 센트/도, 구간 편차 0%  (양호)
```

**구간 편차 20% 초과면 그 회차는 버린다.** 주된 원인:
- 중간에 푸는 방향으로 돌렸다 (가장 흔하다)
- 3초를 안 기다리고 쟀다
- 페그를 돌릴 때 기타가 움직여 마이크 거리가 바뀌었다

### 전체 끝

```
최종 — 6번 줄 E2
  1회차  +0.2069 센트/도
  2회차  +0.2071 센트/도
  3회차  +0.2065 센트/도
  평균   +0.2068 센트/도   회차 편차 0%

  서버가 쓸 값 (tuning_logic.peg_angle 의 k):
    k = 4.836 deg/cent
```

## 7. 문제가 생기면

**"발현을 못 찾음"이 반복된다**
마이크가 소리를 못 받고 있다. 장치를 확인한다.
```bash
python3 tools/mic_level.py
```

**"측정이 N센트 흔들립니다" 경고**
주변 소음이 크거나 발현이 약하다. 조금 더 세게 뜯는다.

**"탐색 범위를 ±5반음으로 넓혀 잡음"**
한 번에 너무 크게 돌렸다는 뜻이다. 각도를 줄인다.

**값이 회차마다 크게 다르다**
백래시 규칙(3절)을 안 지켰을 가능성이 가장 높다.
회차 시작 때 충분히 풀었다가 조여 올렸는지 확인한다.

## 8. 아직 안 잰 것 — `peg_calibration.yaml` 의 나머지 3칸

각도-센트는 끝났지만 `config/peg_calibration.yaml` 은 네 칸이 다 차야
`measured: true` 로 올릴 수 있다. 이슈 #8 참조.

### 최소 유효 각도

이보다 작게 돌리면 페그가 실제로는 안 움직인다. 이 값이 없으면 오차가 작을 때
0에 가까운 각도를 반복 전송하며 조절 횟수만 소진한다.

```bash
python3 tools/peg_cal.py --string 6 --min-angle
```

사다리를 각도가 아니라 **센트 기준**으로 짠다(2/3/5/8/12센트). 실측한 줄별
민감도로 각도를 역산하므로 줄마다 사다리가 달라진다. 6번 줄은 0.9~5.4도,
1번 줄은 4~24도가 된다. 각도 고정 사다리로는 줄마다 다른 질문을 묻게 된다.

판정은 두 가지를 다 본다. 같은 각도를 3~4번 이어 돌려서

- **누적비** — 총 변화가 기대의 70% 이상인가
- **고른비** — 각 회가 기대의 절반~1.5배 안에 드는 비율이 60% 이상인가

누적만 보면 안 된다. 줄이 너트에 걸렸다 튕기면 0/0/큰값이 나오는데 누적은
기대치를 채운다. 그 각도로 한 번 명령하면 결과가 0이거나 3배라 조율 루프가
진동한다. 실제로 쓸 수 있으려면 **매번 고르게** 움직여야 한다.

> **수렴 한계**: `최소 유효 각도 x 센트per도 <= 허용 센트(10)` 여야 한다.
> 줄별 상한은 6번 4.5도 / 5번 11.6도 / 2번 9.4도 / 1번 19.9도다.
> **6번 줄이 4.5도를 넘으면 그 줄은 10센트로 수렴할 수 없다.** 허용 센트를
> 늘리거나 기구를 손봐야 하므로, 넘으면 바로 팀에 공유할 것.

### 백래시 양 — 페그 교시 후에 잴 것

```bash
python3 tools/peg_cal.py --string 6 --backlash --step 15
```

⚠ **지금 재면 다시 재야 한다.** 최종 백래시는 페그 자체 + 그리퍼가 페그를 무는
헐거움의 합이다. `motion_primitives._grip()` 주석대로 파지 폭을 확정한 뒤에
재야 한다. 현재 `teach_points.yaml` 의 페그 4개는 전부 `taught: false` 다 (이슈 #10).

### max_angle_deg

1회 goal 의 회전량 상한(안전). 실측보다 합의 사항이다.
`min_effective_deg` 보다 커야 한다 — 작으면 `peg_angle()` 의 최소각 보정이
`min(angle, max)` 에 무효화되어 페그가 안 움직이는 각도를 보낸다.

## 9. 결과 전달

정동휘에게 이 형식으로 넘긴다. 도구가 마지막에 그대로 출력해준다.

`config/peg_calibration.yaml` 에 바로 들어가는 형식이다.

```yaml
      s6:   # 6번 E2 82.4069Hz
        cents_per_deg: 2.219        # ✅ 측정 완료 (2026-09-19)
        min_effective_deg: 0.0      # --min-angle
        max_angle_deg: 0.0          # 합의 사항
        backlash_release_cents: 0.0 # --backlash (페그 교시 후)
```

측정 완료분 (목표 ±30센트 구간 기준, `docs/페그_실측표.md`):

```
6번 E2   2.219 센트/도
5번 A2   0.865 센트/도
2번 B3   1.065 센트/도
1번 E4   0.502 센트/도
```

넣을 값은 전 구간 평균이 아니라 **목표 ±30센트 값**이다. `peg_angle()` 이
`|오차| / cents_per_deg` 이므로 작게 잡으면 각도를 크게 계산해 과조정한다.

`k = 1 / (센트per도)` 가 `tuning_logic.peg_angle()`에 들어간다.
줄마다 값이 다르므로 **줄별 표**로 갖는 게 맞다. 지금 코드는 상수 하나다.

JSON은 `peg6.json` 등으로 저장되니 그대로 첨부해도 된다.

## 10. 한계

- 손으로 돌린 각도는 로봇만큼 정확하지 않다. 특히 45도 이하에서 오차가 크다
- 사람이 잡는 힘과 로봇 파지력이 달라 기어 물림이 다를 수 있다
- **로봇이 준비되면 같은 절차를 자동으로 반복해 재측정한다. 그때가 진짜 값이다.**
  이 측정은 계산식의 초기값과 안전 범위를 잡기 위한 것이다
