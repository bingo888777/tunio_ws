# task_manager 구현 브리핑 양식

작성일 2026-09-19 · 채울 사람: 정동휘 · 받는 쪽: AI agent

---

## 이 문서는 뭔가

`task_manager`를 구현하려면 저장소 문서만으로는 답이 안 나오는 항목이 있다.
이 양식은 **그 항목만** 추린 것이다. 기획서·ICD·인터페이스 명세에 이미 답이 있는 건 여기 없다.

빈칸을 채워서 주면 그 범위까지 구현한다. **빈칸은 내가 임의로 메우지 않는다.**

---

## 답하는 방법

- 번호마다 한 줄이면 된다. 이 파일에 직접 써도 되고, 채팅에 `A1: 0.12` 식으로 번호만 붙여 줘도 된다.
- 숫자에는 단위를 붙여라 — 도 / 센트 / 초 / 회 / Hz.
- 모르면 셋 중 하나로 명시해라. 빈칸으로 두지 말고.
  - `모름` — 아직 값이 없다. → **그 자리는 구현하지 않는다.** 함수는 만들되 `NotImplementedError`를 던지거나
    호출 직전에 `PHASE_ERROR`로 멈추게 둔다. 그럴듯한 숫자를 넣지 않는다.
  - `확인중` — 팀에 물어봐야 한다. → `모름`과 같게 처리하고, 어디에 물어볼지 TODO 주석에 남긴다.
  - `맡김` — 아무 값이나 괜찮다. → 내가 정하되 상수 한 곳에 모으고 `# 임시값, 미합의` 주석을 단다.
- 이 양식 밖의 내용을 바꿔야 한다고 판단되면 나는 묻기만 하고 손대지 않는다.

---

## 0. 이미 정해져 있다고 보고 안 묻는 것

내가 이렇게 읽었다. **틀린 게 있으면 여기부터 고쳐 줘.**

- 줄 순서 6 → 5 → 2 → 1, 목표 주파수 4개는 `tuning_logic.TARGETS` 값 그대로 고정
- 센트 오차 = `1200*log2(측정/목표)`, 절댓값이 `tolerance_cents` 이내면 성공
- 측정 1회 시퀀스는 ICD 6.1 — measure goal → ready feedback → play_string goal →
  PlayString Result와 MeasurePitch Result **둘 다** 받은 뒤 진행. 둘의 도착 순서는 보장 없음
- 측정 실패(success=false)면 페그 안 건드리고 재측정, `measurement_id`는 매번 증가
- `measurement_id`는 **작업 단위**로 1부터 증가 (줄이 바뀌어도 리셋 안 함)
- `job_id`는 task_manager가 `"20260922_143015"` 형식으로 생성
- 결과 Result의 job_id·string_number·measurement_id 3개를 대조해서 안 맞으면 버림
- 취소는 DB에 저장 안 함. 자동 복귀 없음. 재개 불가
- `tuned_hz` = Phase 1에서 **마지막으로 얻은 유효 측정값**
- 유효값 없으면 `has_*_hz=false`, DB는 NULL. 0Hz 금지
- 설정 초기값: 10센트 / 조절 5회 / 재측정 3회 / 측정 타임아웃 10초 / onset 10초 — 전부 임시값
- `/tuning/state`는 reliable · depth 1 · transient local
- `MeasurePitch.FAIL_*` 0~4는 `StringResult.FAIL_*`로 번호 그대로 복사 가능

- A1-2. 줄마다 다른 값을 쓰나, 한 값으로 퉁치나?

- A1-3. 선형으로 봐도 되나? (페그 회전각이 커지면 센트 변화가 비선형이면 알려 달라)

- A2-2. 음이 **낮은** 경우(조이는 방향)에도 풀었다-조이기 2단계를 하나, 바로 조이기 1번으로 끝내나?

- A2-5. 백래시 양 실측값이 있나? (peg_cal.py 백래시 모드 결과)
  → `A2-5:`

### A3. 회전량 하한·상한

- A3-1. **최소 유효 각도** — 이보다 작게 돌리면 페그가 아예 안 움직이는 각도.

- A3-2. 1회 최대 회전각. 현재 코드는 20도로 잘라 놨는데 근거가 없다.

- A3-3. 계산된 각도가 최소 유효 각도보다 작으면 뭘 하나?
  (① 최소 각도로 올려서 돌린다 ② 조절 포기하고 현 상태로 성공/실패 판정 ③ 다른 것)

## E. 구현 방식 — 추천은 있는데 확인은 받아야 하는 것

### E1. 동시성 구조

측정·발현이 서로 다른 Action이고 둘의 Result 도착 순서가 보장되지 않아서, 구조 선택이 코드 모양을 크게 바꾼다.

- ① `MultiThreadedExecutor` + 별도 스레드에서 상태기계를 순차 코드로 (동기식, 읽기 쉬움)
- ② 콜백 체인 + 명시적 상태 변수 (단일 스레드, ROS 관례에 가깝지만 코드가 흩어짐)
- ③ `rclpy` async/await

추천은 ①. pause/resume/cancel이 끼어들기 때문에 "지금 어느 단계냐"를 코드 흐름 그대로 읽을 수 있는 쪽이 디버깅에 유리하고,
`robot_controller`가 이미 `MultiThreadedExecutor`를 쓰고 있어 결이 맞는다.

- E1-1. 어느 쪽?
  → `E1-1:`
