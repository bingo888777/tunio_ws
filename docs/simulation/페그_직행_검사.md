# 피크 반환 후 페그 직행 검사 — 2026-09-23

결론: **현재 교시된 팔 자세 계열과 높은 접근점으로는 90도 경유점을 단순 삭제할 수 없다.**
검사한 8개 직행 후보 모두 높이와 J5 조건을 위반했다. 모든 sol·높이·중간 자세를
탐색한 결과는 아니므로, 경유 없는 경로 자체가 불가능하다는 뜻은 아니다.
실제 로봇이나 두산 서비스에 연결하지 않았다.

## 조건과 코드 반영

- 사용자 확인: J1 -60→-90→-120(방향상 +240)의 짧은 구간은 기타 헤드 때문에 금지.
  실제 절대 관절각은 -60~240도 안에서만 이동한다. 끝점 포함, 현재각을 임의 환산하지 않는다.
- 기존 Base Z 하한 214mm와 모델 여유 5mm 유지. TCP·J3~J6 원점·손목 케이싱
  검사 지점이 높은 이동 중 219mm 이상이어야 한다. 반환 후 TCP는 Z=224mm.
- J5 허용치는 기존 135도에서 여유 5도를 뺀 ±130도. J6는 ±280도 미만.
- 공통 높은 경로 검사에 J1 전체 범위 검사를 추가했다. 기존 -90도 한 점 통과 검사보다
  넓은 금지 구간을 반영한다. **자동 운전의 90도 경유점은 삭제하지 않았다.**

## 시뮬레이션 결과

피크 거치대의 현재 사용 계열(J1 약 -14.24도)과 반대 계열(J1 약 +166.93도)을
수치 IK로 계산했다. 실제 현재 관절값을 읽은 것이 아니다. 각 계열에서 6·5·2·1번의
높은 접근점(Z=224mm)까지, 페그 손잡이 회전각 0도 기준으로 관절 선형 보간했다.

최저 검사 높이(현재 계열 / 반대 계열):

- 6번: 195.7 / 152.5mm. 목표 J5 -132.34도.
- 5번: 185.9 / 151.5mm. 목표 J5 -132.83도.
- 2번: 151.3 / 183.7mm. 목표 J5 +133.07도.
- 1번: 152.9 / 194.9mm. 목표 J5 +132.58도.

앞서 바꾼 “높은 접근점에서 이미 페그 파지 방향을 갖는 방식”이 실제 교시 좌표에서는
제한을 만족하지 않는 것으로 드러났다. 모의 API 테스트 통과와 실제 좌표의 경로
성립은 다른 문제다. 기존 검사가 이 목표를 거부하므로 제한을 풀어 강행하지 않는다.

## 자기충돌 검사 범위

설치된 dsr_description2의 m0609.white.urdf 충돌 메시를 trimesh로 읽고 python-fcl로
검사했다. 드라이버/메시를 이 저장소에 복사하지 않았다. 링크 변환은 저장소의 M0609
기구학 체인을 사용한다. MoveIt SRDF의 인접 및 Never 충돌 제외 쌍을 적용했다.

- 최대 관절 간격 0.5도, 8개 경로 합계 2,782개 표본에서 검사 대상 팔 링크 간
  충돌은 검출되지 않았다. 최소 메시 간 거리는 약 28.7mm였다.
- 검출기 점검: 영점 자세는 비충돌, [0,90,150,0,90,0] 접힌 자세는 실제 메시 충돌로 검출.
- **RG2·고무 골무·피크·케이블·기타·거치대 외형은 이 충돌 모델에 포함하지 않았다.**
- 높은 접근점 이후의 하강·삽입은 이번 검사 범위 밖이다. 높은 구간부터 실패했다.
- 수치 IK를 쓰므로 두산 sol 번호·실제 보간 궤적을 검증한 것이 아니다.
  표본 사이의 충돌도 완전히 배제하지 못한다. “자기충돌 없음/안전”의 인증이 아니다.

## 재현

별도 Python 환경에 numpy scipy trimesh python-fcl pycollada pyyaml이 필요하다.
이번에는 /tmp/tunio-path-sim 환경만 사용했고 로봇 실행 의존성에는 추가하지 않았다.

```bash
OPENBLAS_NUM_THREADS=1 /tmp/tunio-path-sim/bin/python tools/peg_transfer_sim.py \
  --description /home/mook/ws_cobot_pjt/ws_dsr/src/doosan-robot2/dsr_description2 \
  --srdf /home/mook/ws_cobot_pjt/ws_dsr/src/doosan-robot2/dsr_moveit2/dsr_moveit_config_m0609/config/dsr.srdf.xacro \
  --output docs/simulation/peg_transfer_direct.json
```

원자료: [peg_transfer_direct.json](peg_transfer_direct.json). 시작/목표 관절각, 표본 수,
충돌 제외 쌍, 검사 결과를 포함한다.

다음 조정은 높이·J5 제한을 유지하면서 높은 접근점의 팔 자세와 방향을 다시 선정하는 것이다.
필요하면 J1=90도 고정 경유 대신 상승·자세 전환용 중간 자세를 검토한다.

## 후속 변경: J5 제한 제거

사용자 요청으로 J5 소프트웨어 제한을 제거했다. 위 J5 실패와 원자료는 변경 전
설정의 기록이며, 이후 시뮬레이터는 J5 합격/불합격을 판정하지 않는다.
높이 위반 결과는 그대로 유효하다. movej는 관절각을 보간하므로 출발·도착 TCP가
모두 Z=224mm여도 중간 손끝 높이는 유지되지 않는다. 특히 팔 자세와 손목 방향을
함께 바꾸면서 플랜지에서 208mm 떨어진 TCP가 아래쪽으로 휘는 경로를 만든다.
하한 검사는 이 경로를 거부할 뿐, 스스로 위로 우회하도록 경로를 만들어 주지는 않는다.
