# J6 회복 단독 점검 → 통합 테스트

실기 도구는 운영 코드의 joint_states 감시 콜백과 `_recover_j6`를 재사용한다.
실제 회복/간섭 여부는 작업자가 확인한다. 자동 테스트 통과는 실기 검증이 아니다.

## 실행

두산 드라이버는 켜고 robot_controller, 서버 조율 및 다른 조그/이동 도구는 종료한다.
이 도구는 robot_controller가 발견되면 실행을 거부하지만 모든 외부 명령원을 잠그지는 못한다.
접촉이 없는 위치와 손목·피크·케이블의 180도 회전 공간을 확인한다.

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
python3 tools/j6_recovery_check.py
python3 tools/j6_recovery_check.py --execute
```

- 첫 명령은 joint_states로 J6만 조회한다. TCP 설정이나 이동 명령은 보내지 않는다.
- `--execute`는 기존 connect()로 TCP/툴을 확인·설정한다. 현재각과 회복 목표를 출력한 뒤
  `RECOVER`를 입력해야 회복한다. 그리퍼 개폐·집기·페그 조절은 하지 않는다.
- 현재 |J6|가 280도 미만이면 **이동하지 않는다**. 이는 실기 회복 성공이 아니다.
  280도 이상, 설정된 300도 한계 이내인 상태에서 회복을 확인한다.
  도구가 일부러 한계 근처까지 돌리거나 시험 시작 자세를 만들지는 않는다.
- +285→+105, -285→-105처럼 180도 줄어드는지 확인한다. J1~J5 실제각도 함께 대조한다.
  회복은 YAML의 기본 속도 30도/초, 가속도 60도/초²를 사용한다.
- 확인 중 자세가 바뀌거나 관절 조회/감시/회복이 실패하면 오류로 끝낸다.
  자동 재시도나 원래 각도로 복귀하지 않는다. Ctrl+C는 로봇 정지 명령이 아니다.

## 판정과 기록

`recovered`는 운영 함수의 도달각 대조가 통과했다는 뜻이다. 육안 간섭 확인은 별도다.
빈손에서 양방향 회복을 확인하고, 피크를 든 상태도 회전 공간과 이후 발현·반환을 확인한다.
실제로 시험한 방향/피크 유무를 기록한다. 한쪽만 시험하면 반대쪽은 미검증으로 남긴다.

기록은 기본 `~/.tunio/robot_data/*_j6_recovery_check.json`이다. 실행 결과·전후 관절각·
수신한 J6 표본과 시각·오류를 남긴다. 회복 중 감시값이 계속 들어오는지도 확인할 수 있다.
이 검사는 이동 도중 보호정지 방지나 모든 자세의 충돌 안전을 보증하지 않는다.

확인 후 도구를 종료하고 정상 노드를 다시 켠다. **별도 페그 재등록 → 한 줄 통합 →
4줄 통합** 순서로 진행한다. 시작 버튼은 등록하지 않는다. 높이 검사에 막히는 접근
경로는 여전히 별도 확인 대상이며 기타 영역 지정·우회 경로 개선은 뒤로 미룬다.
