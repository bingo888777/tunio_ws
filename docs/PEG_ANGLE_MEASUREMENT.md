# 페그 회전량 실측 가이드 — 수동 측정판

로봇팔 없이 손으로 페그를 돌려 "페그를 몇 도 돌리면 음이 몇 센트 변하는가"를 구한다.
이 값이 있어야 `task_manager`가 측정 오차로부터 `AdjustPeg`의 `angle_deg`를 계산할 수 있다.

로봇 준비 후 재측정이 필요하다. 이 수동 측정은 계산식의 초기값과 안전 범위를 잡기 위한 것이다.

---

## 0. 먼저 정할 것 — 어느 각도인가

기타 페그는 기어로 감속된다. 보통 14:1이다.
손잡이를 14바퀴 돌려야 줄이 감기는 축이 1바퀴 돈다.

**여기서 재는 각도는 손잡이(버튼) 각도다.** 로봇도 손잡이를 잡고 돌리므로 기준이 같다.
축 각도로 환산하지 않는다. `AdjustPeg`의 `angle_deg`도 손잡이 각도다.

사용하는 기타의 기어비를 알면 기록해 둔다 (페그 제조사 표기 또는 손잡이 회전수 세기).

---

## 1. 준비물

- 실제 시연에 쓸 기타 (다른 기타로 재면 값이 다르다)
- 주파수 측정 수단 — 정정인의 분석 스크립트가 있으면 그것, 없으면 휴대폰 튜너 앱 중 **Hz를 소수점까지 보여주는 것**
- 마스킹테이프와 유성펜
- 각도기 또는 인쇄한 각도 눈금 (없으면 아래 시계 방식)
- 기록지 (아래 양식)

### 각도 표시 만들기

손잡이에 마스킹테이프를 붙이고 한쪽 끝에 선을 긋는다. 이것이 기준선이다.
헤드 쪽에도 테이프를 붙여 0도 위치를 표시한다.

각도기가 없으면 시계 방향으로 세면 된다.
- 45도 = 1/8바퀴
- 90도 = 1/4바퀴
- 180도 = 반바퀴
- 360도 = 한바퀴

---

## 2. 측정 원칙

**항상 조이는 방향으로만 돌린다.**
페그에는 유격(백래시)이 있어 방향을 바꾸면 처음 얼마간 헛돈다.
값이 튀는 가장 큰 원인이므로 반드시 지킨다.

**되돌릴 때는 목표보다 아래로 충분히 푼 뒤 다시 조여 올린다.**
1회 측정이 끝나고 다음 회차를 시작할 때 이렇게 한다.

**목표 음 근처에서 잰다.**
줄이 너무 느슨하면 같은 각도라도 음이 훨씬 적게 변한다. 목표 음 ±1반음 안에서 측정한다.

**손을 뗀 뒤 2~3초 기다리고 측정한다.**
줄과 기어가 자리를 잡는 시간이 필요하다.

---

## 3. 측정 절차

대상 줄: **6번(E2, 82.41Hz)과 1번(E4, 329.63Hz)** 최소 두 개.
시간이 되면 5번(A2, 110Hz), 2번(B3, 246.94Hz)도.

저음과 고음 양 끝을 재면 나머지는 사이값으로 추정할 수 있다.

### 한 줄당 순서

1. 목표 음보다 살짝 낮게 맞춘다 (약 -50센트, 6번 줄이면 80Hz 근처)
2. 손을 떼고 3초 뒤 주파수를 측정해 기록한다 → 이것이 시작값
3. 손잡이를 **90도(1/4바퀴)** 조이는 방향으로 돌린다
4. 3초 뒤 주파수를 측정해 기록한다
5. 3~4를 **4회 반복**한다 (총 360도, 한 바퀴)
6. 줄을 다시 시작 위치보다 아래로 풀었다가 조여 올려 1번 상태로 되돌린다
7. 1~6을 **3회 반복**한다

90도씩 4단계를 도는 이유는 한 바퀴 안에서도 값이 일정한지 보기 위해서다.
값이 크게 들쭉날쭉하면 기어 상태나 줄 감김에 문제가 있다는 신호다.

### 고음 줄 주의

1번 줄은 같은 각도에도 음이 크게 변한다. 90도가 너무 크면 45도로 줄인다.
반대로 6번 줄에서 90도로 변화가 너무 작으면 180도로 키운다.
**어느 각도로 쟀는지 반드시 기록한다.**

---

## 4. 기록 양식

줄마다 이렇게 적는다. 회차별로 한 묶음.

```
줄: 6번 (목표 82.41Hz)    회차: 1    단위 회전: 90도

시작      80.15 Hz
+90도     81.02 Hz
+180도    81.95 Hz
+270도    82.80 Hz
+360도    83.71 Hz
```

Hz는 소수점 둘째 자리까지 적는다. 측정값이 흔들리면 눈으로 보이는 중앙값을 적는다.

---

## 5. 센트 환산

Hz는 줄마다 기준이 달라 비교할 수 없다. 센트로 바꿔야 한다.

```
센트 = 1200 × log2(나중 주파수 / 처음 주파수)
```

위 예시로 계산하면:

```
전체 변화 = 1200 × log2(83.71 / 80.15) = 75.2 센트
360도에 75.2센트  →  1도당 0.209 센트
```

파이썬으로 하면 한 줄이다.

```python
import math
def cents(f_new, f_old):
    return 1200 * math.log2(f_new / f_old)
```

구간별로도 계산해 본다. 90도 구간 4개의 센트가 서로 비슷해야 정상이다.

```
0→90도    1200×log2(81.02/80.15) = 18.7센트
90→180도  1200×log2(81.95/81.02) = 19.8센트
180→270도 1200×log2(82.80/81.95) = 17.9센트
270→360도 1200×log2(83.71/82.80) = 18.9센트
```

편차가 ±20% 안이면 쓸 만하다. 한 구간만 확 튀면 그 회차는 버리고 다시 잰다.

---

## 6. 최종값 산출

줄마다 3회차의 "1도당 센트"를 평균한다.

```
6번 줄
  1회차  0.209 센트/도
  2회차  0.198 센트/도
  3회차  0.215 센트/도
  평균   0.207 센트/도
  편차   ±4%
```

편차가 20%를 넘으면 측정 방식에 문제가 있다. 방향을 섞어 돌렸는지, 대기 시간을 지켰는지 확인한다.

### 서버가 쓸 계산식

```
필요 각도(도) = 오차(센트) ÷ (해당 줄의 센트/도)
```

예: 6번 줄이 목표보다 15센트 낮으면 → 15 ÷ 0.207 ≈ 72도 조인다.

측정 안 한 줄(5번, 2번)은 6번과 1번 값 사이를 주파수 기준으로 보간한다.
정확하지 않지만 첫 시도용으로는 충분하다. 실제로는 한 번에 안 맞아도
루프가 돌면서 수렴하므로 초기값이 대략만 맞으면 된다.

---

## 7. 같이 재면 좋은 것

### 백래시 양

조이다가 방향을 바꿔 풀 때, 몇 도를 돌려야 음이 실제로 떨어지기 시작하는지.

1. 조이는 방향으로 맞춘 뒤 주파수 기록
2. 푸는 방향으로 15도씩 돌리며 매번 측정
3. 주파수가 처음 떨어지기 시작한 누적 각도가 백래시 양

이 값을 알면 "목표 아래로 얼마나 풀어야 하는지"를 정할 수 있다.
백래시가 40도면 여유를 둬서 80~100도쯤 풀었다가 조여 올리면 된다.

### 안전 각도 상한

한 번에 최대 몇 도까지 돌려도 되는지.
목표 음에서 시작해 조이는 방향으로 돌리며 **+200센트(2반음)를 넘지 않는 선**에서 멈춘다.
그 각도의 절반 이하를 로봇의 1회 최대 각도로 잡는다.

**줄을 끊지 않도록 조심한다.** 시연 전에 여분 줄이 없으면 복구가 어렵다.
목표보다 높아지면 즉시 멈추고 풀어 내린다.

### 최소 유효 각도

너무 작게 돌리면 유격에 묻혀 아무 변화가 없다.
15도, 30도, 45도를 각각 돌려 보고 음이 실제로 변하기 시작하는 지점을 찾는다.
이 값보다 작은 각도는 서버가 요청하지 않도록 하한으로 쓴다.

---

## 8. 결과 전달 형식

정동휘에게 이 형태로 넘긴다.

```
기타: (모델명)
기어비: 14:1 (확인 안 되면 미상)

6번 E2   0.207 센트/도  (3회 평균, 편차 ±4%)
1번 E4   0.412 센트/도  (3회 평균, 편차 ±7%)

백래시   약 40도
안전 상한 180도
최소 유효 20도
```

이 값이 `task_manager`의 회전량 계산식과 `AdjustPeg` 요청 각도의 범위 제한에 들어간다.

---

## 9. 한계

- 손으로 돌린 각도는 로봇만큼 정확하지 않다. 특히 45도 이하에서 오차가 크다
- 사람이 잡는 힘과 로봇의 파지력이 달라 기어 물림이 다를 수 있다
- 줄은 시간이 지나면 늘어난다. 새 줄이면 값이 계속 변하므로 **줄을 갈고 하루 이상 지난 상태**에서 잰다
- 로봇팔이 준비되면 같은 절차를 자동으로 반복해 재측정한다. 그때가 진짜 값이다
