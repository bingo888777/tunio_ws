# 피크 확인 — 성현 최종 결정 (2026-09-22)

## 세 검사 구간

1. 거치대에서 피크를 집고 닫힘이 안정된 뒤, 들어 올리기 전.
2. 피크로 줄을 튕기고 줄에서 후퇴한 뒤.
3. 일시정지 후 재개한 요청 중 피크가 필요한 동작이며, 피크를 들고 있던 경우.

일반적인 타현 직전 검사는 추가하지 않는다. 페그 파지·피크 반환 상태에는 피크 문턱을
적용하지 않는다. 판정·재집기·알람·복귀는 robot_controller 내부에서 수행한다.

## 빈손과 읽기 실패는 다른 상태다

- 정상 폭 13.5~16.0mm: 계속 진행한다 (2026-09-23 실기 재시험 잠정 하한).
- 실제 읽은 폭이 13.5mm 미만: 빈손이다. 거치대에서 재집기를 최대 2회 한다.
  최초 빈손 감지에 사용한 집기는 이 추가 2회에 포함하지 않는다.
  재집기 성공 시 원래 작업 흐름을 이어간다.
- 재집기 두 번 모두 실제 빈손: 관제에 알람 → 홈 복귀 시도 → 실패 Result → 서버 작업 종료.
- 폭 읽기 실패: 앞서 합의한 재읽기 1회를 유지한다. 두 번 모두 읽지 못하면
  관제에 '피크 폭 읽기 실패/확인 불가'를 알린 후 동작을 계속한다.
  재집기 중이어도 빈손 실패 횟수로 세지 않는다. 확인을 못 했다는 뜻이지 빈손이 아니다.
- 너무 큰 폭은 이물질 끼임 가능성이 있어 별도로 이동 없이 중단한다.
- 로봇 이동 실패를 빈손으로 취급해 재시도하지 않는다. 실패 상태·사유를 그대로 보존한다.

거치대 접촉점에서 빈손이면 수직 후퇴를 먼저 한다. 재집기는 거치대에서 그리퍼를
열고 시작해 오판했더라도 임의 위치에 피크를 놓지 않는다.
2026-09-23 실기 후 수정: 집기 실패 후에는 거치대 상단 위치를 확인하고 바로
재하강한다. 중간 반환 동작과 홈/대기 자세 왕복은 없다. 타현 후·재개 검사에서
빈손이면 안전 경유와 위치 확인을 포함한 거치대 반환을 처음 한 번만 수행한다.
닫힘 안정화 후 들어 올리기 전 폭 검사는 유지한다. 후퇴나 반환 중 예외가
나면 상태를 모름으로 남겨 자동 재집기를 막는다.
타현 후 재집기 성공은 타현 자체를 추가 실행하지 않는다. 마이크 측정 결과와 재측정은
기존 서버 흐름에서 처리한다.

## 메시지와 관제 표시

- 기존 재개 버튼: `/tuning/resume` Service.
- 서버 → 로봇: `PlayString.Goal(string_number, resumed)`. 서버는 재개 사실만 전달한다.
- 로봇 → 서버: `PlayString.Feedback.warning`으로 폭 읽기 실패 또는 재집기 소진 알람.
- 서버 → 관제: 기존 `/tuning/state` Topic의 `robot_notice` → web_node → SSE →
  실시간 작업 화면의 알림 영역. 서버는 로봇 문구를 그대로 전달하고 폭을 판단하지 않는다.
- 읽기 실패만 있고 동작 완료: success=true Result, message에 경고 보존. 조율 계속.
- 재집기 소진: 홈 복귀 완료/실패를 포함한 success=false Result. 서버는 추가 Goal을 보내지 않는다.
- 알림은 새 작업 시작 시 비운다. 경고만으로 발현을 중복 요청하지 않는다.

별도 피크 확인 서비스는 없다. `PlayString.Goal.resumed`, `PlayString.Feedback.warning`,
`TuningState.robot_notice`가 추가돼 양쪽 PC 모두 인터페이스·노드를 재빌드해야 한다.
피크 Feedback은 발현 시점 신호가 아니며 오디오 onset 판정은 그대로다.

재집기로 play_timeout_sec를 넘기면 같은 Goal의 종료 결과를
robot_completion_wait_sec(기본 120초, 실기 검증 전 임시값)만큼 더 기다린다.
그래도 응답이 없으면 작업을 중단하며 새 Goal/자동 복귀를 추가 요청하지 않는다.
이 대기는 물리 정지 명령이 아니다.

최신 main `f1b1f1d`(#81·#83·#85·#86 병합본)에 로컬 피크 변경을 통합했다.
반환 위치 확인·높이 검사, 로봇 성공 Result 확인, 네 페그 등록 선행 조건을 유지한다.
로봇 실패가 서버 예외로 전달돼도 관제 사유 표시·마이크 취소 후 종료한다.
실기 검증은 아직 하지 않았다.
