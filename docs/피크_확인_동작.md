# 피크 확인·관제 보충 대기 (2026-09-23 성현 정정)

## 판정

피크 판정은 **있음 / 없음** 두 가지다.

- 정상 폭 13.3~16.0mm는 있음. 그 밖은 없음.
- 폭 읽기 실패는 한 번 재읽고, 두 번 모두 실패하면 없음으로 처리한다.
  통신 실패 원인은 로봇 로그에 남긴다. '모름' 판정이나 경고 후 진행 분기는 없다.
- `verify_pick=false`는 검사 자체를 생략하는 시험 옵션이다.
- 로봇 이동 중 예외로 생긴 위치·파지 불확실성은 별도 안전 상태다.
  이것을 피크 없음으로 바꾸거나 자동 재집기로 처리하지 않는다.

13.3mm 하한은 피크를 잡았는데 13.4mm로 읽힌 실기에 맞춘 잠정값이다.
빈손 13.2mm와 0.1mm 차이이므로 반복 실측을 통한 검증은 남아 있다.

## 검사 시점

1. 거치대에서 닫힘 안정화 후, 들어 올리기 전.
2. 줄을 튕기고 줄에서 후퇴한 뒤.
3. 일시정지 후 재개 시 피크가 필요한 동작이며 피크를 들고 있던 경우.

페그 파지에는 적용하지 않는다. 판정·재집기·복귀는 robot_controller 담당이다.

## 없음 → 재집기 → 홈 대기 → 웹 재개

없음이면 거치대에서 **추가 2회** 재집기한다. 최초 집기는 추가 2회에 포함하지 않는다.
타현 후 감지했으면 안전 경유로 거치대 상단에 접근하고, 상단 위치 확인 후 그리퍼를
열고 내려간다. 닫힌 채 거치대로 들어가지 않는다. 재집기 사이에는 수직 후퇴만 하며
홈으로 왕복하지 않는다.

재집기 두 번 모두 없으면 다음 순서로 진행한다.

1. 로봇이 홈 복귀를 완료한다.
2. Action을 ABORTED로 끝내면서 `success=false`, `pick_refill_required=true`를 보낸다.
3. 관제는 기존 녹음의 종료를 확인한 뒤 PHASE_PAUSED로 대기한다.
4. 화면에 '피크 없음. 피크를 재보충하고 재개 버튼을 누르세요'를 표시한다.
5. 사용자가 보충하고 기존 재개 버튼을 누르면 새 PreparePluck(resumed=true)을 요청한다.
6. 로봇이 거치대에서 새 집기를 시작한다. 또 추가 2회까지 실패하면 홈 대기를 반복한다.

대기에는 Action 시간 제한이 적용되지 않는다. 홈 복귀 실패는 보충 대기가 아니라
일반 오류로 중단한다. 대기 중 취소하면 새 이동 없이 작업을 끝낸다.
재개 요청 없이 새 동작을 보내면 로봇이 거부한다. 보충 대기는 측정 재시도를 소모하지 않는다.

타현 후 보충 대기에 들어갔다면 이전 녹음을 사용하지 않고, 재개 후 새 준비·녹음·타현으로
측정한다. 홈 대기 없이 자동 재집기에 성공한 경우에는 기존 타현을 반복하지 않는다.

## 데이터 흐름

로봇 PreparePluck/PlayString Result.pick_refill_required + message
→ task_manager의 PHASE_PAUSED / robot_notice
→ /tuning/state Topic → web_node → SSE → 관제 알림·재개 버튼.

웹 재개 → HTTP /api/command/resume → /tuning/resume Service
→ 새 PreparePluck(resumed=true) → 집기 → 마이크 준비 → PlayString.

판정값을 서버로 보내 재판정하지 않는다. 서버는 bool 결과 필드로 보충 대기를 구분하고
알림 문자열을 파싱하지 않는다. 두 Action Result에 필드가 추가돼 양쪽 PC에서
인터페이스를 재빌드하고 관련 노드를 재시작해야 한다.

## 터미널 단독 시험

`pick_reload_prompt=true`는 기존 Enter 방식 시험 전용이다. 홈에서 같은 Action 안에
머물며 새 Enter 뒤에 집기를 반복한다. 관제 운용은 기본값 false로 실행해야 웹 재개가
동작한다. 관제와 터미널 대기를 동시에 쓰지 않는다.

## 페그 동작과의 구분

RegisterPeg·AdjustPeg는 피크 보충 루프를 호출하지 않는다. 피크를 들고 있다면 먼저
반환한 뒤 페그 작업을 수행한다. 페그 자체의 파지 폭 판정과 등록·회전 오류는 별도다.
보충 대기 중 들어온 페그 요청은 차단하며, 페그 작업으로 보충 대기를 해제하지 않는다.
