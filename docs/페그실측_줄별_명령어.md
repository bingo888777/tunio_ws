## 4. 줄별 명령어

### 공통 규칙

- **`--save` 를 절대 빼지 않는다.** 빼면 화면에만 남고 저장소에 아무것도 안 남는다 (#55)
- **`--device` 는 붙이지 않는다.** 기본값이 USB 마이크고, 번호는 PipeWire 가 계속 민다
- **`--repeat 5`.** 3회면 고른비가 0/33/67/100 네 값뿐이라 388% 짜리가 67% 로 통과한다
- **`--robot-timeout 180`.** 기본 60초는 `turn_vel 2.0` 에서 아슬아슬하다
- **백래시 `--step 3`.** 예상 백래시(약 10도)의 1/3 이하여야 한다. `run_backlash` 는
  −5센트에 닿는 **첫 점에서 멈추므로** 단위 각도가 크면 점이 몇 개 안 남고,
  두 점 미만이면 역산을 못 해 누적각을 그대로 백래시로 적는다.
  근거와 환산표는 `docs/페그_캘리브레이션_가이드.md` 백래시 절 (PR #61)
- **백래시 먼저, 최소 유효 각도 나중.** 백래시가 푸는 방향이라 끝나면 음이 낮아져 있고,
  최소 각도는 조이는 방향이라 그대로 이어진다
- **백래시 전에 그 줄을 목표 근처로 맞춰 둔다.** 도구가 "조이는 방향으로 맞춰두세요" 라고
  묻고 멈춘다. `python3 ~/bin/peg_nudge.py --string <번호>` 로 맞추면 된다
- **세기를 일정하게 뜯는다.** 3dB 차이가 1.5센트 편향이다. 2센트 변화를 보는 측정이라
  세기 차이가 그대로 신호로 둔갑한다 (`docs/페그_실측표.md` §4.1)

### 2번 줄 B3 — 246.9417 Hz

```bash
python3 tools/peg_cal.py --string 2 --backlash --robot --step 3 \
    --robot-timeout 180 --save docs/peg_data/$(date +%F)_peg2_backlash.json

python3 tools/peg_cal.py --string 2 --min-angle --robot --repeat 5 \
    --robot-timeout 180 --save docs/peg_data/$(date +%F)_peg2_minangle.json
```

사다리 (cpd 1.065 가정) — `1.9 / 2.8 / 4.7 / 7.5 / 11.3도`, 수렴 한계 `9.4도`.
**7.5도까지 안에서 걸려야 허용 10센트로 수렴한다.**

### 1번 줄 E4 — 329.6276 Hz

```bash
python3 tools/peg_cal.py --string 1 --backlash --robot --step 3 \
    --robot-timeout 180 --save docs/peg_data/$(date +%F)_peg1_backlash.json

python3 tools/peg_cal.py --string 1 --min-angle --robot --repeat 5 \
    --robot-timeout 180 --save docs/peg_data/$(date +%F)_peg1_minangle.json
```

사다리 (cpd 0.502 가정) — `4.0 / 6.0 / 10.0 / 15.9 / 23.9도`, 수렴 한계 `19.9도`.
**15.9도까지 안에서 걸려야 한다.**

### 5번 줄 A2 — 110.0000 Hz (센트/도 확인)

백래시는 9/21 에 9.6도로 나왔지만 **점이 3개뿐이라 `--step 3` 으로 다시 재는 게 좋다**
(6절). **최소 유효 각도는 반드시 다시 봐야 한다** — 6절 참조.

```bash
python3 tools/peg_cal.py --string 5 --backlash --robot --step 3 \
    --robot-timeout 180 --save docs/peg_data/$(date +%F)_peg5_backlash_v2.json
```

먼저 **로봇 스윕으로 센트/도를 확정한다.** 9/19 값(0.865)은 사람이 손으로 돌린 것이고,
9/21 로봇 회차는 1.24가 나왔다. 같은 방식(스윕)으로 로봇이 재야 사과 대 사과다.

```bash
python3 tools/peg_cal.py --string 5 --robot --rounds 2 --steps 3 --step 20 \
    --robot-timeout 180 --save docs/peg_data/$(date +%F)_peg5_sweep_robot.json
```

회차마다 "목표보다 50센트 낮게 맞추세요" 라고 묻는다. `peg_nudge` 로 맞추고 엔터.
2회차 × 3단 = 6구간이라 9/19 스윕(6구간)과 그대로 견줄 수 있다.
20도 × 3단이면 −50센트에서 시작해 대략 +25센트에서 끝난다. 줄 보호 상한(+200센트)에 안 닿는다.

**그 결과로 센트/도가 확정되면**, 그 값으로 최소 각도를 다시 잰다:

```bash
python3 tools/peg_cal.py --string 5 --min-angle --robot --repeat 5 --cpd <확정값> \
    --robot-timeout 180 --save docs/peg_data/$(date +%F)_peg5_minangle_v2.json
```

`--cpd 1.238` 이면 사다리가 `1.6 / 2.4 / 4.0 / 6.5 / 9.7도`, 수렴 한계 `8.1도` 가 된다.

## 5. 소요 시간

`turn_vel 2.0 deg/s` 에 접근·파지·놓기·후퇴가 붙어 **회전 1회 ≈ 1분**이다.

```
백래시          최대 12회전            약 15분
최소 유효 각도  5단 x 5회 = 25회전     약 40~55분
로봇 스윕       2회차 x 3단 = 6회전    약 20분
```

**줄당 1시간.** 2번·1번·5번 재측정까지 하면 **3시간쯤** 잡아야 한다.

**사람이 계속 옆에 있어야 한다.** 페그는 로봇이 돌리지만 **줄은 사람이 뜯는다.**
매 측정마다 "엔터 후 줄을 뜯으세요" 가 뜬다.

## 6. 9/21 까지의 결과와, 판정할 때 주의할 것

### 6번 E2 (완료, PR #43)

```
백래시            10.4도  = 23.4센트
최소 유효 각도     2.3도   (잡음 한계이지 기계 한계가 아니다 — 실측표 §4.1)
센트/도           2.250 실측 (yaml 2.219 와 1.4% 일치)
```

### 5번 A2 (백래시만)

```
백래시            9.6도    역산 기울기 -1.212 센트/도  (점 3개, --step 5)
최소 유효 각도     보류 — 아래 참조
```

⚠ **9.6도는 약간 과소평가일 수 있다.** `--step 5` 로 재서 점이 3개뿐이다.
6번 실측으로 만든 환산표(가이드 백래시 절)에 따르면 `--step 5` 는 참값 10.4도를
10.0도로 읽는다. 5번의 참값도 10도 근처일 가능성이 높다. **결론(각도 가설 지지)은
안 바뀌지만**, `backlash_release_cents` 에 넣기 전에 `--step 3` 으로 다시 재는 게 낫다.

**백래시가 6번 10.4도와 4% 차이다.** `backlash_release_cents` 의 **'각도 기준' 가설**이
두 줄에서 맞았다는 뜻이다 — 백래시는 센트가 아니라 각도로 생기고, 줄마다 각도를 재서
그 줄의 `cents_per_deg` 로 환산해 넣으면 된다. **2번·1번도 10도 근처면 확정이다.**

### ⚠️ 최소 유효 각도 판정을 그대로 믿지 말 것

도구는 5번을 **9.2도** 라고 찍었지만 **판정에 쓴 `cents_per_deg 0.865` 가 의심스럽다.**

원자료에서 뽑은 실제 기울기 —

```
백래시 역산 (푸는 방향)     -1.212 센트/도
5.8도 단 2~5회차            29.43센트 / 23.2도  =  1.268
9.2도 단 1~4회차            44.85센트 / 36.8도  =  1.219
─────────────────────────────────────────────
합                          74.28센트 / 60.0도  =  1.238
```

방향이 다른 세 구간에서 1.22~1.27로 모인다. yaml 의 0.865보다 **43% 높다.**

`1.238` 로 다시 판정하면 **5.8도가 먹힌다** — 5.8도 단의 2~5회차가 `152/155/138/142%`
로 찍혀 "들쭉날쭉" 으로 잘렸는데, 제 값으로는 `106/108/96/99%` 로 아주 고르다.

**이 차이가 실무에서 갈린다:**

```
9.2도 x 1.238 = 11.4센트  →  허용 10센트를 넘는다. 이 줄은 수렴 못 한다
5.8도 x 1.238 =  7.2센트  →  통과
```

도구는 `9.2 x 0.865 = 8.0센트` 로 계산해 "수렴 한계 안" 이라고 했지만, 제 값으로는
안 들어온다. **9.2를 그대로 넣었으면 5번이 조용히 수렴 실패했을 것이다.**

0.865 의 출처는 `docs/peg_data/peg5.json`(9/19) 이다. 6구간 0.728~0.928, 흩어짐 23.7%
로 그 자체는 탄탄하고 **음높이 구간도 겹친다**(107.4~110.0 Hz). 다른 점은 하나다 —
**9/19 는 사람이 손으로 돌리고 각도를 입력한 회차**이고 9/21 은 로봇이 돌렸다.
손으로 "90도 돌렸다" 고 친 게 실제로 60도였다면 센트/도가 그만큼 작게 계산된다.

> 과거에 "yaml 의 cents_per_deg 가 틀렸다" 는 주장을 두 번 냈다가 두 번 철회했다
> (실측표 §4.1). 이번은 근거가 다르다 — 독립된 세 구간, 회전 방향도 다름, 전부 로봇.
> 그래도 **아직 "확인이 필요한 불일치" 이지 확정이 아니다.** 4절의 로봇 스윕이 가른다.

### 그래서 2번·1번은 어떻게 하나

**사다리가 틀린 cpd 로 짜이더라도 그냥 돌린다. 다시 재지 않는다.**

#55 를 고쳐서 이제 `[실제각도, 측정_hz, 센트변화, 기대센트, 비율, RMS]` 가 회마다
남는다. **재측정 없이 재판정이 된다.** 세 줄을 다 돌린 뒤 제 값으로 한꺼번에 다시
판정하면 된다.

세 줄이 다 같은 방향으로 어긋나면 그건 **"사람 손 vs 로봇" 계통 차이**라 한 번에
정리되고, 5번만 어긋나면 5번을 따로 보면 된다.

## 7. 자주 나는 것

### `빈손 <폭>mm` 이 뜬다

```
MotionError: pegs.2: 빈손이다 (폭 16.2mm). 페그를 빗나갔다.
기타가 밀렸거나 교시 좌표가 어긋났다 (#31)
```

**이 문구의 두 원인은 둘 다 아니다.** `docs/robot_data/README.md` 에 오진으로 기록돼 있다.
기타 위치를 손대지 말 것.

페그 손잡이는 축에 대칭이라 **어느 각도로 서 있어도 폭이 19.6~32.8mm** 다.
**그보다 작은 값은 그리퍼가 허공을 문 것이다.** 원인은 대개 둘 —

1. **빌드를 안 했다** (0절). 설치본의 `sol` 이 `null` 이면 로봇이 매번 다른 해를 골라
   손목이 뒤집힌 자세로 간다. 9/21 의 5번·2번 실패가 전부 이것이었다.
   그때 남은 기록이 `docs/peg_data/2026-09-21_peg2_backlash.json` 이다 —
   **기준만 재고 `점` 이 빈 채로 끝난 회차다. 2번 측정값이 아니다**
2. 그래도 나면 `python3 tools/sol_check.py --peg <번호>` 로 해를 다시 본다

### 팔이 하늘을 보거나 엉뚱한 데로 간다

같은 원인이다. `sol` 을 확인한다.

### 측정이 `창 불일치 NN센트` 로 실패한다

다른 줄이 같이 울렸거나 발현이 약한 것이다. **재시도로 흡수된다.** 4회 중 2회만
성공하면 값이 나온다. 계속 나면 뮤트를 확인한다.

### `⚠ 직전 측정보다 NdB 세게/약하게 뜯었습니다`

발현 세기가 음높이를 바꾼다(0.516 센트/dB). **경고가 뜬 회차는 그만큼 편향돼 있다.**
계속 뜨면 세기를 일정하게 잡고 그 단을 다시 한다.
