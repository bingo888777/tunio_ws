# 2026-09-23 관제·오디오·로봇 통합 진행 기록

## 이번 PR에 남기는 범위

사용자 요청에 따라 일시정지·재개 시험 직전 코드 `7f408f3`을 기준으로 정리한다.
대상 브랜치는 `feat/web-peg-registration-alert`, 기존 PR은 #102다.
이 정리는 정상 동작 또는 실물 안전성을 새로 인증하는 것이 아니다.

- 웹 페그 재등록·복귀 완료 후 조율 1회 허용. 다음 작업은 다시 등록한다.
- 미등록 시작 안내 팝업, 중복 팝업과 잘못된 작업 시작 안내 보완.
- 등록 단계 황금색, 조율 단계 파랑색으로 구분.
- 사용자 취소의 정상 종료와 오류 종료 구분.
- 별도 MoveStop(mode=2)·CheckMotion 경로, 취소 후 후속 명령 차단과 복구 잠금.
  이 Soft Stop 구현은 포함하되 실물 검증 완료로 표시하지 않는다.

## 제외하는 시험 변경

`feat/robot-pause-resume-test`의 `ec40127`은 별도 보관하며 이 PR에 포함하지 않는다.
일반 이동 비동기 전환, 목표 도달 검사, /robot/pause·resume, 관제 연동,
관련 시험·문서는 그 시험 브랜치에만 있다. PR 생성·병합은 하지 않았다.
시험 브랜치에 함께 들어간 symlink-install 웹 경로 수정도 이번 기준에는 포함하지 않는다.
직전 코드 웹 실행은 기존 일반 빌드 방식을 사용한다.

## 사용자 실물 보고와 확인된 한계

초기 통합에서 사용자는 취소 후 **현재 이동이 끝난 뒤 정지**했다고 확인했다.
당시 새 정지 코드는 원격에 없었으므로 이 보고는 새 Soft Stop의 실물 검증이 아니다.

이후 시험 브랜치의 통합에서는 다음 로그가 전달됐다.

- 등록 요청 직후 `register_peg goal 거부`. 관제 로그만으로 로봇 측 거부 조건을 확정할 수 없다.
- 별도 실행에서 6번 줄 79.750Hz 측정, PlayString 성공, 페그 조임 25.57도 요청까지 진행.
- 이후 `일시정지 확인 실패: 로봇 일시정지/재개 서비스 미연결`로 작업 오류 종료.
- 사용자는 취소도 동작하지 않는다고 보고했다. 로봇 측 취소 수락·MoveStop·IDLE 로그를
  확보하지 못해 실제 정지 요청 처리 여부 및 원인은 미확정이다.
- 사용자는 양쪽이 시험 브랜치라고 확인했다. 서비스 목록 조회에서 pause/resume이
  보인 시점도 있었지만, 별도 클라이언트의 연결 검사 시점에는 준비되지 않았다.
  이후 노드 종료도 확인되어 버전 불일치나 DDS 설정 하나를 원인으로 단정하지 않는다.
- Ctrl+C 뒤의 `rcl_shutdown already called`는 별도 종료 처리 오류다.
